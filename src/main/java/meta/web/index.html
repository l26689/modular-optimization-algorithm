满意度函数怎么写？（点开看约定）

代码必须是一个完整类，类名固定为 UserObjective，不要写 package：

import meta.ObjectiveFunction;

public class UserObjective implements ObjectiveFunction {
    @Override
    public double evaluate(double[] x) {
        // 返回满意度：越大越优
        return 0.0;
    }
}
  • evaluate(double[] x) 返回满意度，越大越优。 若要最小化 f(x)，请写 return -f(x);。
  • 解 x 的长度等于「数据维度」，各分量落在数据上、下界之间。
  • 必须是纯函数：相同输入必须返回相同输出。不要用 Math.random()、System.currentTimeMillis() 或可变的静态状态，否则结果没有意义。
  • 必须返回有限值：遇到除零、log 非正数、sqrt 负数， 请在函数内部改返回一个有限的大惩罚值（如 -1e12）， 不要返回 NaN 或无穷。
  • 可以自由添加辅助方法与静态字段，例如把数据表直接写在代码里。

提交时会自动编译并试跑：语法错误会指出行号， 返回非有限值或非纯函数也会被拦下。

⚠️ 结果只对当前满意度函数 + 当前预算有效。 换一个函数或换一档预算，最优组合可能完全不同——这是 No Free Lunch 定理的直接后果。

排名第一是从众多候选中挑出来的，存在「胜者诅咒」式的乐观偏差， 它很可能只是这次抽样里运气最好的那个。若要严格验证， 请用不同的随机种子复跑后再对比。

若两个组合的均值之差小于其标准误的 2 倍，该排名差异不可靠，请提高「重复运行次数」。
